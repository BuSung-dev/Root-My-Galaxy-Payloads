and every result so far on the FZG1 port, so the next session can continue

- Port the CVE-2026-43499 payload flow (proven on SM-S9210 `e1q-S9210ZHS6DZG1`,

## 4. Key hypothesis: kernel phys load

- FZF5 doc value `0x80080000` is an sboot-Exynos convention; sboot does not
  exist on Snapdragon, so it was rejected for this port.
- Working hypothesis: `P0_KERNEL_PHYS_LOAD = 0xa7e58000` (proven on S918B,
  corroborated by UEFI memory map entry `0xA8000000,0x10000000,"Kernel"`
  found by scanning the unpacked `uefi.elf`, entry `0xa7000000`).
- The APP build logs confirm the profile in use, e.g.:
  `phys_offset=0000000080000000 kernel_phys_load=00000000a7e58000 ...`.

## 5. Payload engineering fixes during the campaign

- **Slide**: 3-anchor quorum (`0x1b5b44 / 0x10db44 / 0x1e1284`, `MIN_VOTES 2`).
  Slide is now stable every round (typical `0x80000 / 0x1F0000 / 0xD0000`,
  64 K-aligned). File: `src/slide.c`.
- **Leak**: fixed; rounds reliably print
  `mm leaked + page prepare base=...`. File: `src/main.c`.
- **APP fd bug**: `open_slide_selected_fds` overwrote fds 0-2; fixed in
  `src/slide_app.c` / `src/fops.c`. Verified via `dm3q-app-psel.so`
  (SHIFT 0-4 all panic with the same signature before the fix path).
- **pselect forensics**: every pselect panic has the same signature
  `rb_erase+0x10 <- rt_mutex_adjust_prio_chain+0x5ac <- adjust_pi ...`,
  `x8` zero with `0xff` bytes nearby → spray structurally not reaching
  the walker. SHIFT 0-4 route declared dead for now.

## 7. Invariant failure signature (the fact to beat)

Every mcast round, regardless of coarse delay or waiter OFF, ends with:

```text
slide mcast returned domain=10 level=41 option=46 offset=0xNN
  ret=-1 errno=99 calls=1 sched_ok=1 last_sched_ret=0 last_sched_errno=0
app fops stage=trigger-return attempt=1 triggered=1
cfi misc_fops mismatch ret=0 target=ffffff802aae4f28
  read=0000000000000000 want=ffffff89xxxx1180 errno=0
```

Zero variance across ~50 rounds. `ret=0 read=0 errno=0` (read "succeeded"
with 0 bytes) is suspicious and motivates a read-path audit (§8, option 1).

## 8. Interpretation and next moves

BREAKTHROUGH 09-29 (build `d47cbea1` = oracle set + `APP_TRACEFS_SLIDE`):
`SLIDE_ONLY=1` auto run → `slide-kaslr-ok source=tracefs base=...080b8000
slide=0xb8000 data_mode=canonical`, 57 events quorum `hits=27`, EXIT=0
(log `slideonly-250929.log`). Tracefs works in adb-shell context, no EACCES.
True slide is `0xb8000` — NOT the `0x90000` forced through the whole
tick sweep: a forced slide is only valid for the boot it was observed on;
every reboot invalidates it. All forced-`0x90000` rounds (smoke, ticks,
errno, control) shot at a stale slide, which alone explains the invariant
`triggered=1 → step-4 0/0` (race writes something, address-dependent
read-back fails). Further: `0xb8000` is 0x8000-granular, off the P0
`32x0x10000` grid — the physical-scan fingerprint (`best=0`) could NEVER
match (same as S918B's `0x78000/0xf8000`). P0-scan KASLR is structurally
dead for this granularity; tracefs is the path. FZG1 was the only family
target without `APP_TRACEFS_SLIDE` (S918B/e1q/S916B all have it).

Follow-up runs (build `6b7466a5` = oracle set + TRACEFS_SLIDE +
tracefs-fresh, logs `full-250929-auto.log`, `full-250929-tracefs.log`):
- auto P0-only (pre-TRACEFS_SLIDE): gate 1/2 then fingerprint `best=0`
  (off-grid as predicted) → `kaslr leak failed`. Confirms grid dead.
- tracefs reliability 2/3 boots: `0xb8000 (hits=27)`, `0x18000` OK; one boot
  single-caller `...212bf30` x141, `candidates=0` → gate failed (vfork=0).
  Trigger workload flaky across boots.
- REQUIRE gate hit a real gap: tracefs-KASLR alone fails
  `main.c:476` (fixed by setting `slide_p0_session_fresh` on quorum success,
  `slide_app.c` guarded).
- P0 fallback infra (same machinery the alias oracle needs): gate tee
  `EFAULT` flaky (hit 1/3), refresh `fcntl F_SETPIPE_SZ → EPERM` SYSCHK-aborts
  the run in shell context (no CAP_SYS_RESOURCE). Refresh path must degrade,
  not die. Gate variance is now suspect #1 per review ordering
  (addresses → trigger → geometry).

Coarse timing (11 values) and waiter offset (7 values) are exhausted on the
tick-`0x30` line with zero signature movement, so the miss is upstream of
both: the fake waiter is structurally not being consumed by the walker,
or the read path never exposes the replacement. Next options in order:

1. **Read-path audit** (~minutes, code only): explain `ret=0 read=0 errno=0`
   in `src/fops.c` / consumer-delay / fd routing — a clean hit should not
   read 0 bytes with errno 0. DONE 09-29 (reviewed, conditional PASS):
   - Fail point `src/fops.c:361-371`: `configfs_read_once` (`src/util.c:2632-2686`)
     returns `pread()` directly with `errno` pre-zeroed, so `ret=0+errno=0`
     only means "0 bytes came back" — zero discriminating power. `pre_fops`
     stays 0 because the buffer was zero-init and 0 bytes were copied.
   - World A (route missed, true ashmem table): fresh fd has `size=0`
     (no `ASHMEM_SET_SIZE` anywhere in `src/`), so 8B read fails. Caveat
     (review): true ashmem has no `.read`/`.read_iter`, VFS should give
     `-EINVAL` not 0 — observed `0/0` may itself be an `errno`-sampling
     artifact (C0 below). Claim downgraded to "8B unreadable (0 or -EINVAL)".
   - World B (route hit, fake table `read=NULL`/`read_iter=configfs_read_iter`):
     `pread` falls back to `read_iter` on an ashmem file, dereferences the
     wrong `private_data`, returns 0 (precedent: `q4q-*/target.h:50-61`;
     note q4q is 5.10 old API, not directly transferable to 5.15 `read_iter`).
     Cannot be excluded, but assuming it begs the question (route-hit is
     what step 4 must prove).
   - The A/B-splitting oracle (`main.c:601-635` postwrite direct read via
     `verify_p0_pipe_data_page`, `src/pipe.c:1163`) is compiled OUT for FZG1:
     no `APP_FOPS_DEFER_ALIAS_READBACK`, and the verify fn itself is guarded
     by `APP_REQUIRE_FRESH_P0_SESSION` (also absent; S918B likewise; only
     e2s/r12s/e1s/e1s-NK 6.x targets carry the full set). Fresh logs show no
     `postwrite` line, as expected.
   - Verdict: prioritize World A (no positive route-hit evidence anywhere),
     not a conviction. Next: (a) save `errno` before `pr_warning` in
     `src/fops.c` fail paths (same disease at least at steps 4/1/3);
     (b) fail-path control read at `pos=0` + print `fd/pos/set_ret/set_errno`
     (necessary, not sufficient); (c) port the full
     `DEFER_ALIAS_READBACK+FRESH_P0+DURABLE_LOG+FRESH_PAGE_ATTEMPTS` set from
     e2s/r12s as the authoritative A/B ruling (changes supervisor retry
     semantics — second phase); (d) if A: stop timing sweeps, attack waiter
     geometry (`MCAST_WAITER_OFF 0x78` / `WORD_SHIFT 4` have no disasm
     derivation, unlike S918B); (e) if B: check which `CONFIGFS_READ_ITER`
     variant 5.15.189 needs.
2. **Tick sweep** (`0x20-0x60` with hybrid speed, ~1 h): bets the deadlock
   window is not at `0x30`. DONE 09-29: all 8 default-list `FINE_TICKS`
   values (`0x00/0x10/0x18/0x20/0x30/0x40/0x60/0x80`), fresh boot each, 8/8

3. **Back to pselect**: needs offline futex-frame math or sentinel OFF scan;
