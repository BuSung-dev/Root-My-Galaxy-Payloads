## Physical load proof

The raw ARM64 Image has `text_offset == 0`. In `sboot.bin`, the code referencing `Starting kernel...` loads the Image text offset, adds `0x80000000`, and branches to the resulting entry point. Therefore:

```c
#define P0_PHYS_OFFSET 0x80000000ULL
#define P0_KERNEL_PHYS_LOAD 0x80080000ULL
```

## P0 table and payload build

`src/targets/dm3q-S9180ZHS8FZF5/p0_fingerprint.h` was generated from the target raw Image for all 32 candidates `0x000000` through `0x1f0000`. Verification read all 256 source qwords back at page offsets `0x000, 0x200, ..., 0xe00`.

The app-domain release payload is built with:

```sh
make TARGET=dm3q-S9180ZHS8FZF5 release
```

The fixed-size result is published at `artifacts/dm3q-S9180ZHS8FZF5/cve-2026-43499-app.so`.

## KernelSU compatibility

KernelSU was built from tag `v3.2.5` with the repository Samsung KDP/RKP/DEFEX patch applied to the official Samsung Open Source `msm-kernel` (Kalama 5.15) tree. 

The module was built with exact target release overriding the DDK vermagic:

```text
vermagic: 5.15.189-android13-8-33413713-abS9180ZHS8FZF5 SMP preempt mod_unload modversions aarch64
```

Because Samsung does not export core symbols like `commit_creds` or `selinux_state`, `Module.symvers` was reconstructed directly from the target `vmlinux.elf` using `nm` extraction. 

Static checks passed against the recovered S9180 `vmlinux.elf`:

```text
undefined symbols: 205
module version entries: 135
missing from target symbol table: 0
missing from target exports: 6
target CRC mismatches: 128
```
*(Note: Missing exports and CRC mismatches are expected for unexported core symbols and are bypassed at runtime via the CVE-2026-43499 arbitrary read/write primitive patching `check_version` during `insmod`)*.
